# Nubrix security & performance audit — 2026-10-31

Scope: branch `nubrix`, commit `45e709e` ("Rename everything to Nubrix"), plus the installed `/Applications/Nubrix.app` and the live Claude Code hook config in `~/.claude/settings.json` (read only). No application code was changed. Severities: Critical / High / Medium / Low / Info. "Verified" means reproduced or confirmed on this machine; "Code" means confirmed by reading the code; "Suspected" means inferred and needs measurement or on-device confirmation.

## Executive summary — top 5 actions

1. **Make the approval channel authenticate the server (S-01).** `nubrix-permission` prints `allow` for any process that answers `{"decision":"allow"}` on the port in the endpoint file. The file outlives crashes and `pkill -9`, and any local process can bind that free port. Verified with a fake server that used the wrong token. Fix: move to a Unix domain socket in `~/.config/nubrix` (0700), or have the hook check an HMAC proof.
2. **Stop running live hooks from the git working tree (S-02).** `~/.claude/settings.json` runs `…/Documents/projects/nubrix/claude-plugin/scripts/*`. A Claude session working in this repo (edits are auto-approved in acceptEdits mode), or a checked-out PR branch, can edit `nubrix-permission` so that every session in every project approves itself. Install the scripts to a sealed path, such as inside the signed app bundle, and point the hooks there.
3. **Ship with hardened runtime and without `get-task-allow` (S-03, S-10).** The installed app is ad-hoc signed, has no hardened runtime, has `get-task-allow`, and carries a stale upstream `BoringNotchXPCHelper.xpc`. Any same-user process can inject code and use Nubrix's Camera, Calendar, Accessibility and Apple Events grants. Fix `scripts/install-local.sh` and do clean builds.
4. **Make the notch card show exactly what gets approved (S-04, S-06, S-07).** Fixes: scan and show the full command, and treat truncated or multi-line commands as risky. Show Write/Edit content. Add an arming delay and accept only real HID clicks. Withdraw all pending prompts on lock, sleep or session switch; today `withdrawAll()` has no callers.
5. **Get Vitrin off the main thread and stop it holding full content (P-01–P-05), and fix data at rest (S-08, S-09).** `reload()` loads up to 1000 rows of full text on main after every clip. Previews decode 3024×1964 images on main; the footprint peak was 269 MB against 57 MB steady. Deleted clip text stays in the FTS index (verified). The store is included in Time Machine backups, and the secret guard misses common secret formats (verified with a test harness).

Server side, only an explicit click produces `allow`. `AgentPermissionStore.allow(_:)` is called from one place only (`AgentViews.swift:113`, the card's Allow button). Every other path (expiry, withdraw, PostToolUse/Stop observation, disabled approvals, full queue) answers `none`. The hook maps only two exact response bodies. The ways around the click are on the client and transport side (S-01, S-02) and in how the click itself is obtained (S-06, S-07).
